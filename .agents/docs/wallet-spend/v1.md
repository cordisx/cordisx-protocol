# Local wallet spend v1

`cordisx.wallet-spend/v1` is an independent optional capability. Its [types](../../../types/wallet-spend.v1.d.ts) and [source schema](../../../schemas/wallet-spend-source.v1.schema.json) do not extend frozen HTTP v1–v4 or work-income contracts. Hosts without the capability return unsupported through consumer downgrade behavior. Consumers must not substitute renderer confirmations, ordinary bearer requests, arbitrary signatures, or another wallet.

## Authority and source trust

The Host derives the existing original enrolled local wallet. Callers cannot supply an account, wallet key, economic URL, bearer, approval Boolean, signing callback or money baseline. `identity` returns public receipt-key metadata only. Funding comes exclusively from the admitted actual Host model-usage income path. Devices and local administrators can tamper with their software or keys; neither a local signature nor package digest proves unforgeable usage or global double-spend prevention.

`authorizeSource` fetches fixed public metadata over the actual canonical HTTPS origin, validates its server ID and Ed25519 key, and asks for native approval of that exact identity and caller. Inline self-signed terms alone never establish ownership of the claimed origin. The Host persists the pin for the actual caller identity. Rotation requires explicit native approval; older keys remain recovery-only for existing reservations. Renderer code cannot overwrite pins or register funding authorities. Bind and reserve independently verify live HTTPS metadata against the active pin. A separately deployment-provisioned existing local loopback Game process may use canonical HTTP localhost/127.0.0.1/IPv6 loopback with its fixed key. This is local-device trust, not HTTPS origin attestation; authorizeSource never dynamically admits HTTP or loopback sources. No remote service gains access to the local authority.

`bindGameAccount` accepts only the signed fixed Game challenge (`economy.spend-wallet-challenge/v1`) and returns the original wallet's fixed proof (`economy.spend-wallet-binding/v1`). The Game service must issue and consume its nonce under the logged-in Game account, atomically store the binding, and reject silent key reassignment. No Codex credential or local wallet bearer crosses to Game.

## Reservation and finality

The signed economic documents use the portable `@cordisx/economy/spend` v1 contracts: `economy.spend-terms/v1`, reservation, decision and settlement; public method arguments carry their signed JSON envelopes as strings, not executable objects. Ed25519 keys are canonical unpadded SPKI DER base64url, signatures canonical 64-byte base64url. Signing bytes are UTF-8 `payload.contract + NUL + sorted canonical JSON(payload)`. Terms and decision hashes are SHA-256 of canonical payload JSON, excluding the signature. The [fixture](../../../test-vectors/wallet-spend.v1.json) provides reproducible cross-provider inputs. This capability grants no general signing authority.

`reserve` validates the complete exact signed terms, original wallet participation, source pin and admission deadline. An independent trusted native confirmation displays the same immutable terms, own maximum consumption, all bindings and complete terms hash. Approval directly invokes the privileged economic authority's atomic reservation. No approval handle is returned to a plugin to execute substituted parameters. The authority persists the reservation and random nonce before signing a public receipt, which the client transports to Game.

Every stable request ID must be persisted before the call. The original wallet, source, ID and terms uniquely identify the reservation. Retry returns the durable original receipt; differing terms conflict. `lookup` can recover after an uncertain result. The admission deadline only prevents new reservations. Offline, timeout, abort, process retirement or expired terms never release committed funds automatically.

`applyDecision` accepts only the matching service's signed, durable, immutable decision. Origin, service key, server, account, wallet/key, match, terms hash, reservation, nonce and principal must match persisted state. Capture is an integer from zero through that participant's original frozen amount. The remainder returns to that same reservation. Refund captures zero. There are no payouts, recipient credits, cross-wallet transfers or game-win minting; game results use separate points. Decision consumption, ledger changes, release and receipt persistence are one transaction. Conflicting finals are rejected and remain disputes, not grounds for automatic refund. Mutually untrusted services may equivocate and compromised devices may forge signatures; the protocol does not guarantee global finality.

## Local commerce and historical reads

Catalog, purchase, order and orders address only a provisioned caller/store binding. The local authority re-reads its catalog, constructs an immutable purchase quote with item, quantity, price, target, stable order ID and original wallet, and requires independent native confirmation. Expected price is a guard, not pricing authority. Final mutation rechecks catalog and target and commits the order, inventory and debit atomically. Replay recovers the existing exact order without another debit. Native rejection commits an authoritative same-request cancellation tombstone while its session remains valid. Explicit cancelPurchase confirms the exact original body, without requiring a now-changed catalog price. Purchase and cancellation are mutually exclusive in the same canonical transaction; cancellation recovers an existing order if it already committed. Order queries may return either the exact order or cancellation receipt. Missing and unavailable never imply cancellation. No remote Game terms may authorize a shop purchase.

`legacyReceipt` is an exact read of an original saved operation key and body against the canonical wallet. Missing means null. It never submits an old operation again, creates a missing receipt or fabricates historical signed evidence. Retired remote-economy writes cannot enter the new flow.

## Lifecycle and errors

Host caller, owner/source, runtime/module generation, deadline, original-wallet revision and source pin fence dispatch and publication. The private authority authenticates the local transport, retires its session synchronously on disconnect, and checks that session at the final transaction. Retirement and mutation linearize at the economic authority: a transaction committed before retirement remains committed. The Host suppresses stale publication and reports outcome-unknown when mutation may have happened. Cancellation cannot undo a completed reservation or purchase. Consumers recover it rather than retrying with a new ID.

Permission is fresh fixed-purpose native authorization, not a persistent general spend grant. Trusted renderer dialogs are not security isolation against malicious code sharing their realm. The native confirmation process, secret, local authority, database and receipt signer stay outside that realm. OS owner/admin compromise remains outside the guarantee. Unsupported hosts and missing deployment authority fail explicitly; a type declaration or server-only engine does not establish runtime adoption, deployment or acceptance.
