# Controlled Markdown editor v1

Normative framework-neutral editing behavior. Public handle import:
`@cordisx/protocol/controlled-markdown-editor/v1`. Host bindings may provide
framework-specific properties, events and accessibility attributes.

A controlled editor accepts a text value and emits user changes. It supports
Markdown syntax highlighting, Host theme/font updates, bounded automatic height
and native text selection. Programmatic value synchronization MUST NOT duplicate
user-change events. The editing surface must preserve IME composition and native
keyboard events; the consumer owns submission, shortcuts, mentions, menus,
toolbars and draft persistence. It MUST NOT submit a message by itself.

The imperative handle exposes only `focus`, `getSelection` and `setSelection`.
Selection offsets use UTF-16 indices, matching the native text editing APIs;
protocol message length limits continue to count Unicode code points. A disabled
editor is read-only. Unmount releases observers, styles and editor resources;
late updates cannot touch a replacement instance. Focus/selection on an unmounted
handle is harmless. The binding forwards declared accessibility names and
relations, and emits composition and selection changes needed by a consumer-owned
suggestion menu. No Room model, command context, Host element query or native
DOM handle is part of this capability.

The existing Host implementation's Markdown/theme/auto-size behavior must remain
available when its business composer retires. A plain textarea is not evidence
of equivalent editor presentation. Other public UI contracts remain frozen.
