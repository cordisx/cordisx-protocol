# Manager collection protocol v2

The [`manager-collection/v2`](../../../types/manager-collection.v2.d.ts)
entrypoint adds a decorative identity visual to the Host-rendered collection.
Registration, query, search, actions, results, routes, permission checks and
source lifecycle retain the complete [v1 semantics](README.md). Only the
snapshot advances to `cordisx.manager-collection-snapshot/v2`, version 2.

`ManagerCollectionRegistryV2.registerV2()` explicitly selects that snapshot.
Inherited `register()` still accepts exactly v1. A producer can use the old
registration with a semantic icon source on an older Host; it must not submit
a v2 snapshot through `register()` or append identity fields to frozen v1.

An identity visual contains exactly `kind: "identity"`, `icon: BrandIconV1`,
and optionally `avatar: RasterImageSnapshotV1`. Both image branches require
the complete [bounded raster validation](../raster-image/README.md), including
semantic PNG checks. No URL, CSS, SVG, HTML, callback, account id, credential,
network request or Agent avatar provider is part of this value.

Without a usable avatar the Host displays the icon. With a usable avatar the
Host displays the account artwork and places that icon in its lower-right
corner. Missing, undecodable or unavailable avatar artwork falls back to the
icon; an invalid contract is rejected rather than fetched. The Host owns
size, clipping, badge geometry, theme contrast and source disposal. Both images
are decorative inside the already labelled card control, with empty image
alternatives. Identity fields do not become search fields or confer authority.

This is useful for connection accounts and other account-backed collections.
It does not redefine an Agent avatar or a Room participant composite, add a
settings form, or let a plugin mount its own card renderer.
