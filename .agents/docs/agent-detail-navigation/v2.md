# Agent detail navigation v2

V2 adds explicit `getV2` and `openV2` methods to the existing service interfaces.
[V1](README.md), its `get`/`open` methods and all v1 schemas remain frozen and
current-only. A v2-capable Host exposes both generations; consumers feature-check
the new methods. Absence means historical detail is unsupported, never a reason
to create/resume an Agent or silently reinterpret v1.

## Exact Session to opaque reference

`AgentSessionDetailReferenceService.getV2({ sessionId })` resolves one exact
same-owner current detail as v1 does, or one authenticated persisted Host
Session mapping when there is no current detail. It returns only the requested
Session identity and an opaque `AgentDetailReference { kind: 'host', ref }`.
No response implies that the Session is loaded, live, working or idle.

The Host authenticates the caller's complete source/plugin identity and current
owner generation, connection and permission. A matching Session name, Room,
definition, plugin id without its source, or caller-provided ownership is not
mapping authority. More than one eligible mapping must return denied
`ambiguous-session`; a known foreign Session must not fall back to another
record. Missing/revoked mappings return a typed unavailable/denied result.

A historical reference is an ephemeral Host-issued capability, bound to that
exact authenticated owner, Session and mapping revision (or equivalent immutable
mapping identity). The Host must recheck the owner/connection after async reads.
It must not issue a capability from a mapping that changed during that read.
Replacing the owner generation, connection or mapping invalidates the old
capability, even if a subsequent generation reuses the same Session id. Raw
persistent identifiers must not be encoded as a public navigation target.

## Open and lifetime

`AgentDetailNavigationService.openV2({ target })` accepts a current reference
under the v1 rules or an issued historical capability. Historical opening
revalidates the current authenticated owner, permission, connection and exact
persisted mapping before invoking the Host navigator. Unknown, forged, foreign,
stale or ambiguous capabilities cannot navigate. Mapping changes invalidate an
old target; the consumer must obtain a fresh target. A reference obtained from
v2 does not grant v1 permission to open a historical Session.

The Host owns destination selection and Back/history. No caller supplies a raw
URL/path, native id, callback, Agent handle, Room route or navigator. A Host that
cannot read an authoritative persisted mapping or open that destination returns
`unsupported`, `detail-unavailable` or another applicable typed unavailable
result. It must not manufacture a route or convert a raw historical URL.

Both methods are view-only: they must not create/resume a Session, start recovery,
submit input, replay history, write a mapping, mutate a persistent ledger or emit
synthetic execution events. Ephemeral capability bookkeeping is not a new
persistent Session store. Owner disposal and connection replacement release or
invalidate the issued capabilities.

## Representations and consumer flow

The [TypeScript entrypoint](../../../types/agent-detail-navigation.v2.d.ts) retains
v1 callable methods and adds v2 methods. The v2 request/result schemas reuse
`agent-detail-reference.v1` and the Session opaque id shape; they do not add a
runtime-status field:

- [get request](../../../schemas/agent-session-detail-reference-request.v2.schema.json)
- [get result](../../../schemas/agent-session-detail-reference-result.v2.schema.json)
- [open request](../../../schemas/agent-detail-navigation-request.v2.schema.json)
- [open result](../../../schemas/agent-detail-navigation-result.v2.schema.json)

A product row with a persisted exact Session association calls `getV2`, retains
its accepted target for interaction and calls `openV2`. It handles nonaccepted
results visibly and may request a fresh target after invalidation. The product
owns the row label and ordering; this API supplies no conversation UI.

## Security and evidence

A renderer-held opaque reference is not proof by itself: authorization remains
with the Host on every get/open. Issuance must not disclose native identifiers,
other owners' existence or content. Sharing or guessing a reference cannot
transfer access. Read and open races require revalidation across the asynchronous
boundary, not merely at method entry. Implementations may choose stricter
unavailable responses for foreign references rather than disclose ownership.

[Conformance](../../../conformance/agent-detail-navigation-v2.mjs) exercises the
closed wire forms and a host-neutral capability model, including source
substitution, mapping/generation/connection replacement and zero execution or
persistent-write effects. Host integration must additionally test its real
mapping authority, service registration and navigation adapter. Conformance
alone does not establish native navigation, Back/history behavior or acceptance.
