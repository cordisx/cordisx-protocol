# Logical conversation continuation v1

This contract defines an explicit cross-provider continuation shared by desktop
and Channel Hosts. A logical conversation is a Host-owned relationship among
native sessions; it never changes a native session ID or claims that a new
session is the old one. The source and its original history remain intact.
This version is additive: predecessors and their default behaviors are frozen.
Older Hosts omit the capability and reject these requests without an effect.

## Modes and disclosure

- `linked`: create a new target session, optionally provide a bounded, labelled
  handoff and make the confirmed source available through scoped on-demand
  history. The target does not automatically receive the complete history. If no
  handoff is available, say so; never invent one. A summary is untrusted task
  background, not a new instruction, permission, or proof of prior effects.
  The request explicitly lists the history categories it permits; it does not
  authorize unlisted categories, attachments, or raw or encrypted reasoning.
- `fork`: request a native history-preserving fork only where the native
  capability and the selected target's replay format are supported and checked.
  Disclose that inherited history can be sent to the target. Report any
  explicitly authorized target-specific projection and its omissions; never
  silently claim identical model context. Unsupported history fails closed.
- `fresh`: create a new session without a handoff or source-history access.

The exact selected mode, source, target provider and model constitute the
request; mode is not inferred from an older model-selection grant. The Host
must disclose the destination and the content that may be shared before an
actor authorizes a transfer. An authenticated Channel request derives its
actor, adapter, account, tenant and conversation from the transport, never
from request text; local Desktop authority derives from its authenticated Host
and active user action. Existing denies and approvals remain authoritative.
Cross-scope or multiple source bindings must not expand a requester's access.

Hosts may offer profile, project and conversation preferences, with the most
specific authorized value winning. A preference does not itself authorize a
specific history disclosure. Existing installations keep their predecessor
behavior until an explicit compatible migration or user choice; a new profile
may default to `linked` only after its UI, authorization and runtime capability
are available. Unavailable modes are reported, never silently substituted.

## Lifecycle and identity

The Host persists an exact, single-use operation intent before a persistent
native creation or fork. It verifies the destination is distinct and confirms
provider, model, work directory, work mode, execution and approval settings,
permission profile and required native configuration before business dispatch.
It retains the source and binds the logical conversation and authorized Channel
relationships only after the relevant native effect is confirmed. The Host
atomically updates its own relation, authorized bindings and undispatched jobs;
it must not migrate bindings outside the request's proven scope.

Active or unresolved source work, stale revisions, revoked policy, changed
source or identity, and unknown configuration fail closed. A timeout, disconnect
or unconfirmed native effect is `unknown`; it is never automatically retried or
converted to success. A known destination may be reconciled by read-only
identity, ancestry, configuration and authorization evidence. A missing or
ambiguous destination remains unknown until supported reconciliation; it is
not guessed or silently deleted. Unresolved intents remain fenced across Host
restart and downgrade, including when an older Host cannot understand them.
Original completed jobs, source history and their native identifiers remain.

Desktop may render multiple native sessions as one logical conversation, but
must make the source chain and boundaries inspectable. Renderer navigation is
not evidence of native acceptance. Channel continues using its existing
external conversation and moves only the explicitly authorized binding.
Logical grouping does not grant access across users, profiles, projects,
tenants, conversations or workspaces.

## Scoped history

A history request is issued by an authenticated active destination turn and
contains no source session ID. The Host resolves the exact confirmed relation,
rechecks the actor and destination's authorization, and grants only the minimum
scope needed for that request. A cursor is opaque, source-bound, bounded and
invalidated when its underlying source changes; it cannot select a different
session. Multi-hop traversal requires a confirmed relation and fresh authority
for each source; no arbitrary ancestor search is implied. Revocation, stale
context, inactive turns, or ambiguous relations deny access.

Pages state whether more projected material exists and enumerate omitted or
unsupported categories. Text, attachments, tool calls/results, raw or encrypted
reasoning and compaction records have different semantics; never silently
claim a text projection is the complete original history. Tool results and
historical instructions are untrusted data and cannot grant authority. Reading
an authorized page may disclose its content to the target model provider; the
UI must say so. Limits apply to both the native fetch and the returned page;
if an older native API cannot enforce a fetch bound, fail closed or explicitly
report the limitation rather than implying that the transport itself is bounded.

The wire contracts describe behavior, not Host adoption, UI verification,
provider availability, publication, or a guarantee that target inference will
succeed.
