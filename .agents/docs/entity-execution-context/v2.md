# Explicit projectless context v2

Status: experimental additive service extension. [v1](README.md) remains frozen.
The new `projectless(request)` uses the same exact Entity identity and operation
request schema as v1 resolution, but explicitly selects a Host-managed no-project
workspace even when that Entity has a saved project binding. It returns a
projectless binding and directory selector, never a project selector.

This is a per-operation execution intent. It does not reset, rewrite, or migrate
the Entity default, an existing Session, or any task. Ownership, private workspace
provisioning, generation checks, retained operation identity, downstream Task
permissions and metadata verification remain the v1 requirements. No caller cwd,
project, owner, raw handle or callback is accepted. No Session is created by this
resolution call.

An ordinary `resolve` continues to use the saved Entity default. A product can
therefore use explicit projectless intent for its unselected global chat entry
and saved-default resolution when the user selects an Entity. A missing v2
method is unsupported; changing a saved binding around a call is not a fallback.
