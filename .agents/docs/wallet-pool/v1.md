# Wallet pool v1

Experimental optional `walletSpend.pool`, contract `cordisx.wallet-pool/v1`.
The owning Economy provider implements collateral, accounting and distribution.
Host only marshals bounded signed documents, pins source and wallet identity,
authorizes the exact principal through native consent, and fences operation lifetime.

`reserve` accepts service-signed `economy.pool-terms/v1` and a persisted request ID.
`lookup` recovers that exact request; null is not proof of cancellation.
`applyDecision` delivers one signed `economy.pool-decision/v1`. Economy validates
all deposit signatures, the complete funded participant set, conservation,
immutable exited allocations, and the ordered previous-hash chain before an atomic
ledger write. Offline consumers replay the original durable chain in order.

Pool terms disclose the original wallet principal, all participants, immutable
service identity, exact game package, total rounds and distribution policy.
Host MUST NOT accept a caller amount, wallet selector, approval callback or
renderer-supplied signer. Different terms under a request ID conflict. A lost
reply after dispatch is `outcome-unknown`; retry uses the original operation.

A provider without pool support MUST fail closed. Consumers MUST NOT substitute
ordinary wallet spending, income grants or legacy financial routes. Existing
`wallet-spend/v1` methods retain their original capture/refund semantics.
Retiring the parent wallet client retires its pool operations too.

## Trust

A signature proves the identity of a signer, not that arbitrary software has
funded a wallet. The service must admit only wallet authorities within its
explicit trust policy before accepting pool receipts. Game authors cannot
mint collateral. Local device owners remain able to alter local files and
software; this protocol alone cannot prevent copied-wallet double spending.
Deployment must not claim a global tamper-resistant currency on that basis.
The service must persist one non-equivocal settlement chain before publishing
it; clients cannot independently refund on timeout or disconnection.

Economy owns the strict money-document codecs and conservation tests; Protocol
owns this host-neutral optional capability and its lifetime/failure semantics.
