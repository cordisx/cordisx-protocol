# Manager Content navigation protocol v5

V5 is the additive successor to frozen navigation v4. It keeps the same
Host-owned plugin configuration body, draft, commands, CAS ledger, default
materialization, persistence writer, application modes, and closure fences.
It adds only a renderer-safe localized label projection for finite scalar
Schemastery choices.

The public entrypoint is
`@cordisx/protocol/manager-content-navigation/v5`. Its machine contracts are
navigation v5, projection v4, plugin-config descriptor/common v3, and Manager
config subscription page v2. Manager config command/result v1 and subscription
close v1 remain authoritative and unchanged.

## Localized finite choices

Form presentation v2 may attach a complete `choices` list to one field:

```ts
{
  path: ['shortcutPolicy'],
  presenter: { version: 1, kind: 'choice.select' },
  choices: [
    {
      value: 'enter',
      label: {
        key: 'composer.shortcut.enter',
        fallback: 'Enter sends',
      },
    },
    {
      value: 'mod-enter',
      label: {
        key: 'composer.shortcut.mod-enter',
        fallback: 'Command/Ctrl+Enter sends',
      },
    },
  ],
}
```

The declaring plugin supplies the same closed form-presentation v2 value as
the root Schemastery `meta.extra.cordisxForm` annotation. The Host validates and
normalizes it into descriptor-v3 `schema.form`; arbitrary `extra` content is
not projected. Consumers may type that annotation with
`ManagerContentPluginConfigFormPresentationV2` from the v5 entrypoint.

`value` is the exact JSON scalar from the resolved field's finite `enum`, or
from every scalar `const` branch of `oneOf`. Each finite value must occur
exactly once in `choices`; duplicate values, missing values, additional values,
non-scalar choices, and metadata on a non-finite field fail closed. Equality is
JSON scalar equality, so `1` and `"1"` are distinct. Choice metadata does not
change validation, defaults, drafts, or persisted values.

Every `label` is `LocalizedText` with a required non-empty `fallback`. The Host
resolves `namespace`/`key` against the declaring owner's active-locale catalog,
using the normal locale fallback chain. When no message resolves, it renders
`fallback`. Unknown fields, malformed text, unresolved metadata versions, or a
choice set that cannot be proven exact make the v5 projection unavailable with
a bounded diagnostic; the Host must not display the raw value as an asserted
localized label.

For Chatroom, a Chinese catalog may resolve the two keys as `Enter 发送` and
`Command/Ctrl+Enter 发送`, while an English catalog resolves the English copy.
The unchanged `draft.save` command still writes only `enter` or `mod-enter`.

## Ownership and lifecycle

Plugins contribute Schemastery and declarations only. Host owns locale
resolution, form DOM, controls, focus, validation, accessibility, draft state,
save/default controls, and persistence. `ctx.settings` stays read-only.
Subscription page v2 carries projection-v4 snapshots under the exact existing
binding; the separate v1 close promise and all generation/declaration fences
remain unchanged. Navigation v1-v4, projection v1-v3, plugin-config v1/v2, and
all Manager config command/result/close v1 bytes remain frozen.
