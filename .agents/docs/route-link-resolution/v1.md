# Route link resolution v1

Normative additive capability. Public import: `@cordisx/protocol/route-link-resolution/v1`.

`resolveLink({id, params?})` produces a canonical Host-generated deep link for an
existing caller-owned route. A page navigation or route service may implement
this capability; consumers must detect its absence on older Hosts.

The Host authenticates source/plugin/generation from the mounted page or service
context. A page-bound method expires with its mount; an old generation cannot
resolve a replacement owner's route. The Host validates the closed reference,
route ownership, parameters, current route/page and outlet authorization before
returning `accepted` with `url`. The link retains the exact Host-owned source,
route and parameter encoding used by its native deep-link handler. Callers
MUST NOT guess or reconstruct that encoding. No owner, source, raw URL, native
identifier, or arbitrary external URL can be supplied as a resolution request.

Resolving does not navigate, write storage, or access the clipboard. Consumers
may display/copy the exact returned URL using their own authorized user gesture.
An accepted URL is a locator, not a bearer permission: opening it revalidates
normal Host routing authority. Revoked/missing routes return `route-unavailable`;
closed-shape errors return `invalid-route`, and inactive callers or Hosts return
the corresponding unavailable code. Internal route and permission errors are not
exposed as raw exception text. A stale route cannot silently resolve another one.

This contract does not modify the frozen navigation-collection-actions v1
clipboard behavior or existing route declarations.

[result](../../../schemas/route-link-resolution-result.v1.schema.json).
