# Manager self-configuration v1

Normative additive capability. Public import:
`@cordisx/protocol/manager-self-configuration/v1`.

`CordisXManagerService.openOwnPluginConfiguration()` asks the Host to open the
calling plugin's own actionable configuration in the Host-owned Manager. It
accepts no arguments. The Host derives the plugin identity and exact generation
from the capability's Cordis context; a caller cannot name an owner, route,
page, URL, contribution, account operation, or configuration value.

Before dispatch, the Host MUST authenticate the current caller and generation,
confirm that its own configuration remains visible, authorized, and actionable,
and confirm that the Manager receiver is available. It MUST recheck caller
liveness after resolving eligibility and before invoking the receiver. A stale,
replaced, inactive, unauthorized, missing, read-only, unusable, or
non-configurable caller returns `unavailable`. A missing, disposed, rejecting,
or throwing receiver also returns `unavailable`.

`opened` means only that the current Manager receiver synchronously accepted
the navigation request. It does not mean that configuration was saved, an
account was added or imported, credentials were accepted, authentication
succeeded, or a service became available. A silent no-op MUST NOT return
`opened`.

The result contains no owner identity, route, availability reason,
configuration data, schema, credential, secret, or private Host handle. The
Host retains destination resolution, authorization, focus, history, and return
behavior. Implementations MUST NOT add a general navigation bus or expose the
private Manager route to the caller.

Hosts that do not provide this additive service are unsupported for this
capability. Cross-version consumers must treat an absent service exactly like
`unavailable` and keep their configuration affordance disabled or honestly
unavailable; they must not reconstruct a route or fall back to private Host
state.
