# Idle Channel model priority v2

This optional successor extends [idle priority v1](idle-model-priority-v1.md) with one explicit grant covering an ordered list of eligible later candidates. All v1 source-idleness, authorization, history, source-fencing, project, execution-settings and uncertainty requirements remain in force. It does not apply to an already-dispatched turn.

Before confirmation, the Host discloses every exact provider and model in priority order, the user and assistant text the selected service may read on demand, and the possible cost of probes. Only candidates permitted for the authenticated actor and compatible with the unchanged source settings may be included. Confirmation binds the exact disclosed list and current priority revision; an expiring one-use grant permits at most one migration. A list or permission change requires a new disclosure. The grant is bound to the same actor, conversation, source, binding, selection and policy revisions as v1 and is explicitly revocable.

After a real source probe establishes unavailability, the Host considers the disclosed candidates in order. It rechecks the unchanged grant, source selection, actor and permissions, checks compatibility, and uses a bounded real synthetic probe without user content or tools. Unavailable, incompatible and inconclusive candidates are not selected. A healthy result establishes only the probe's success at that time. If no candidate qualifies, the input remains undispatched and receives the normal failure handling. Cancellation, changed authorization or uncertain native effects cannot authorize a later candidate or a replay. Only one confirmed destination may be committed and the grant is consumed atomically with the binding migration.

V1 grants retain their exact-target semantics. Older Hosts must reject durable v2 grants rather than silently treating them as v1. Group and multiply bound sources remain outside this contract: an actor's consent alone does not establish authority to disclose other participants' conversation history to a new provider. Providers without a supported real probe and any already-started turn remain outside automatic migration.
