# Idle Channel model priority v1

This optional successor supplements [creation priority v1](model-priority-v1.md). It can move an existing Channel conversation only before a new Channel input has been dispatched. It never retries an earlier turn or interrupts a running one.

An authenticated user may explicitly grant one future linked continuation for an exact source conversation and exact next provider/model in the local profile's current priority order. Before granting, the Host discloses the source, the exact target, that user and assistant text can be read on demand by the target service, and that this can incur probe usage. The grant does not include tools, reasoning, attachments or a checkpoint. The Host binds it to the verified actor, profile, account, tenant, conversation, active binding, source session, source selection and priority revision. It is revocable, bounded in time and consumed when that migration commits. A saved continuation preference or earlier one-time grant is not this consent.

The Host proceeds only when the source is idle, no other effects are uncertain, and an authorized incoming input remains undispatched. A real, bounded synthetic no-tool probe of the current model must establish an authentication, service, network or response-time failure. Unsupported protocols, local setup failures, cancellation and ambiguous probe results are not evidence of model failure. A supported probe of the exact target must establish success. Probe results contain no user content. A successful probe proves only that request at that time.

All applicable actor, dispatch, command, model and history permissions must still allow the action; a deny cannot be bypassed. The first version supports exactly one active direct binding and only queued inputs from the authorizing actor. It revalidates the grant, priority revision, source selection, source configuration, binding, queued inputs and permissions before native creation and at the binding commit. A changed value invalidates the action rather than selecting another model or changing an explicit choice. The new native session retains the source project and security settings and uses the existing linked history restrictions.

Native destination creation uses the existing durable single-use intent and source fencing. Confirm the destination and atomically commit the relation, authorized binding, eligible queued inputs and grant consumption before dispatch. An unknown native effect remains fenced for reconciliation and is never repeated. If creation or dispatch might have started, do not replay the input. Do not infer that a terminal earlier turn had no side effects. Group, multiple-binding, non-probeable and already-started-turn failover remain unsupported. Older Hosts must reject, rather than ignore, durable state containing an active grant.
